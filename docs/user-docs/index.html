Apple IAP Management 10 tính năng

Apple IAP Management — Giới thiệu

Module quản lý In-App Purchases trên App Store Connect thông qua App Store Connect API v2. Cho phép tạo, chỉnh sửa, xem chi tiết, và nhập hàng loạt IAP mà không cần truy cập trực tiếp giao diện App Store Connect.

Quy trình điển hình

  1. Chọn app từ Danh sách apps (lấy từ App Store Connect theo ASC account đang đăng nhập).
  2. Tạo hoặc chỉnh sửa IAP qua Tạo IAP mới / Chỉnh sửa IAP.
  3. Cấu hình giá theo Pricing template (Default hoặc Per-App) — kiểm tra qua Pricing matrix.
  4. Cấu hình availabilities theo từng territory — hoặc dùng Bulk Availabilities cho nhiều IAP cùng lúc.
  5. Submit batch để gửi review qua Submit batch.

Khi nào dùng Bulk Import?

Khi cần tạo từ 20+ IAP trong một lần, ưu tiên dùng Bulk Import wizard thay vì tạo từng cái thủ công. Wizard hỗ trợ Excel template, validate per-row, auto-retry rate-limit, và rollback.

Khác biệt với Apple App Store Connect UI

  • Hỗ trợ bulk operations mà giao diện gốc của Apple không có.
  • Lưu lại pricing template per-app để áp dụng cho các IAP mới.
  • Hỗ trợ preview changes trước khi submit — tránh save oversight.
  • Tự động retry khi gặp rate-limit (X-Rate-Limit headers).

Bulk Import wizard

Tạo nhiều IAP cùng lúc trên App Store Connect bằng Excel template. Wizard 5 bước với validate per-row, preview trước khi commit, và auto-retry khi gặp rate-limit từ Apple API.

Khi nào dùng tính năng này?

  • Tạo từ 20+ IAP mới trong cùng app — tiết kiệm thời gian so với tạo thủ công từng cái.
  • Setup hàng loạt IAP cho app mới chuẩn bị launch.
  • Onboarding game/app từ nguồn khác — đã có sẵn cấu hình giá trong Excel.

Yêu cầu trước khi bắt đầu

ℹ️ Cần chuẩn bị

1. ASC account đã được setup ở Settings (Key ID, Issuer ID, Private key .p8).
2. Pricing template đã cấu hình (Default hoặc Per-App) — xem Pricing templates.
3. File Excel theo template chuẩn (nút Download bulk import template ngay trên trang Apps list, hoặc nút Download template ở header wizard — hiện ở mọi bước).

Hướng dẫn sử dụng từng bước

  1. Tải template và điền dữ liệu

    Template tải được ở 2 chỗ: nút Download bulk import template ở header trang Apps list (không cần vào wizard), hoặc nút Download template ở header wizard — hiện ở mọi bước. Cả 2 nút mở cùng một form chọn locale; file chỉ được tạo sau khi bạn bấm nút tải trong form. Tool sinh file trực tiếp từ parser nên cột không thể lệch với import. Chỉ nhận .xlsx — không nhận CSV.

    Form chọn locale: danh sách 39 locale của App Store, mỗi dòng hiển thị ngôn ngữ · quốc gia/biến thể · mã (locale không gắn vùng hiển thị — ở cột quốc gia, xem mã để phân biệt). Có ô search (khớp cả ngôn ngữ, quốc gia và mã), Select all shown (chỉ áp cho danh sách đang lọc — search "English" rồi Select all shown = chọn nhanh các biến thể English), Clear all, và bộ đếm số locale đã chọn.

    ℹ️ Mặc định KHÔNG tick sẵn locale nào — và không chọn gì vẫn tải được

    Form luôn mở ở trạng thái trống (không ghi nhớ lựa chọn lần trước). Nếu bấm tải luôn mà không tick gì, bạn nhận template chỉ có cột core — hợp lệ, dùng khi chỉ cần tạo IAP + giá và bổ sung localization sau. Tên file thay đổi theo lựa chọn:

    ChọnTên file
    Không chọn locale nàoapple-iap-bulk-import-template-core.xlsx
    Chọn N locale (chưa đủ 39)apple-iap-bulk-import-template-N-locales.xlsx
    Chọn đủ 39 localeapple-iap-bulk-import-template.xlsx

    Hai lần tải cùng số N (nhưng khác locale) sẽ trùng tên — browser tự thêm "(1)". Mở sheet Notes trong file để biết chính xác file đó có locale nào.

    File gồm 2 sheet:

    • IAP Items — sheet dữ liệu, gồm dòng header + 3 dòng sample (Product ID com.vngg.tool.product.sample01–03). Điền mỗi IAP 1 dòng. Không đổi tên sheet — tool tìm sheet theo đúng tên này (file cũ để dữ liệu ở "Sheet1" vẫn đọc được qua fallback sheet đầu tiên).
    • Notes — giải thích từng cột + bảng ví dụ, viết bằng tiếng Anh (quy ước của tool). Import bỏ qua sheet này — giữ hay xóa đều được.

    Số cột tuỳ lựa chọn: 6 cột core luôn có + 2 cột cho mỗi locale đã chọn (chọn đủ 39 locale = 84 cột). Cột core không nằm trong form chọn — không bao giờ bị bỏ:

    ⚠️ 3 dòng sample — THAY bằng dữ liệu thật, hoặc xóa rồi thêm dòng của bạn

    Dòng giữ nguyên Product ID dạng sample được tool tự động bỏ qua khi import — hiển thị rõ warning "3 example row(s) skipped… delete the sample rows or replace them with your data", không tính là lỗi. Nếu upload file mà chưa thay/xóa sample: import tìm thấy 0 IAP và nút Next ở Step 1 bị disable — đây là nhầm lẫn thường gặp nhất lần đầu dùng. Mọi Product ID khác trong sheet IAP Items sẽ được import thành IAP thật trên App Store Connect. Sample rows điền sẵn cặp cột của locale đầu tiên trong lựa chọn (Vietnamese nếu có); template không chọn locale nào thì sample chỉ có cột core.

  2. Mở wizard và upload file (Step 1 — Excel)

    Từ /iap-management/apps/[appId], click nút Bulk Import ở góc phải bảng IAPs. Wizard mở với 5 bước: Excel → Screenshots → Preview → Territories → Result. Ở Step 1, drag & drop file .xlsx vào dropzone — tool parse ngay tại chỗ và hiển thị card xanh: số IAP đọc được + số cặp locale. Warning "example row(s) skipped" (nếu còn dòng sample) cũng hiện ở đây.

  3. Gắn screenshots (Step 2 — không bắt buộc)

    Thêm file screenshot; tool match với Product ID theo tên file. Không có screenshot vẫn tiếp tục được — bấm Next để bỏ qua.

  4. Preview & conflict resolution (Step 3)

    Per-row validation trước khi commit:

    • Row hợp lệ: xanh, sẽ được tạo.
    • Row có lỗi: đỏ, kèm message (vd: không resolve được tier cho Price (USD) từ pricing template).
    • Row warning: vàng, vẫn commit được nhưng cần xem lại.

    Chọn pricing source cho cả batch và toggle Submit to Apple Review after create ở bước này. Nút Execute hiển thị đúng số IAP sẽ tạo.

    Dòng conflict có ghi chú lần import trước. Nếu một Product ID đã tồn tại và lần import gần nhất để nó dở dang, ngay dưới Product ID sẽ có một dòng vàng kèm dấu ⚠ với đúng câu tóm tắt của lần đó — ví dụ Created on Apple · 12/39 locales · missing screenshot. Đây là chỗ phân biệt "đã tồn tại vì làm xong rồi" với "đã tồn tại vì lần trước dừng giữa chừng": dòng có ghi chú thường nên chọn Overwrite để làm nốt, dòng không có ghi chú thì Skip là an toàn. Product ID chưa từng qua Bulk Import sẽ không có dòng này — không ghi chú nghĩa là không có thông tin, không phải là "chắc chắn ổn".

  5. Chọn territory cho cả batch (Step 4 — Territories)

    Bước này quyết định các IAP mới sẽ được bán ở đâu. Mặc định là All countries or regions — mọi territory Apple có, cộng thêm thị trường Apple mở trong tương lai.

    Một lựa chọn áp cho TẤT CẢ row trong batch. Không có override theo từng row ở đây — nếu cần khác nhau, import trước rồi sửa từng item ở form Edit.

    Muốn giới hạn: bấm Selected countries or regions rồi tick những nước cần. Có ô search (khớp tên nước và mã), chip lọc theo châu lục, và Select all N shown / Clear all N shown — hai nút này chỉ áp cho danh sách đang lọc, không phải toàn bộ catalogue, nên số trên nút luôn là số sẽ bị ảnh hưởng.

    ⚠️ "All countries or regions" KHÁC "tick tay đủ hết"

    Hai trạng thái này gửi body khác nhau lên Apple dù danh sách nước giống nhau:

    • All countries or regions → Apple tự thêm thị trường mới khi Apple mở (footer ghi "includes any new market Apple launches later").
    • Tick tay đủ hết → danh sách đóng băng; thị trường Apple mở sau này KHÔNG tự được thêm (footer ghi "new Apple markets will NOT be added automatically").

    Đọc footer để biết mình đang ở trạng thái nào — đó là chỗ duy nhất phân biệt được.

    Nếu tool không tải được danh sách nước từ Apple, bước này hiện lý do và không cho chọn, nút Execute bị disable. Đây là cố ý: gửi một selection rỗng lên Apple chính là Remove from Sale — không ai muốn tạo IAP rồi ẩn nó khỏi mọi nơi. Quay lại và thử lại.

  6. Execute và đọc kết quả (Step 5 — Result)

    Tool tạo IAP lên App Store Connect với concurrency có kiểm soát và tự thử lại khi Apple chặn tạm thời. Đầu màn kết quả là dãy ô đếm — tổng các ô luôn bằng tổng số dòng, nên không dòng nào biến mất khỏi phép cộng:

    • Succeeded — làm xong trọn vẹn
    • Partial — chỉ hiện khi có
    • Skipped — bạn chọn bỏ qua ở Step 3
    • Failed
    • Not sent — chỉ hiện khi có

    Mỗi dòng trong bảng có một nhãn trạng thái. Bốn nhãn, bốn hành động khác nhau:

    Thấy gìNghĩa là gìLàm gì
    nhãn xanh success IAP đã tạo trên Apple, mọi phần đều xong. Không cần làm gì.
    nhãn vàng ⚠ partial IAP ĐÃ được tạo trên Apple, nhưng thiếu ít nhất một phần (locale, giá, ảnh, availability…). Đọc câu tóm tắt ở cột Notes, bấm Detail để xem thiếu đúng chỗ nào — mục Đọc một dòng Partial ngay dưới.
    nhãn đỏ error Dòng này hỏng, không có IAP nào được tạo. Cột Notes tóm tắt lỗi, bấm Detail xem nguyên văn lỗi Apple. Sửa file rồi import lại riêng dòng đó.
    nhãn xám nét đứt not sent Apple chưa hề được hỏi về dòng này. Batch đã tự dừng trước khi tới nó. An toàn chạy lại — không có gì để trùng lặp. Xem Khi batch tự dừng bên dưới.

    Dòng skipped là lựa chọn của chính bạn ở Step 3, không phải sự cố.

Đọc một dòng Partial

partial nghĩa là IAP đã có thật trên App Store Connect nhưng chưa đủ. Không xoá nó đi và làm lại từ đầu — chỉ cần biết thiếu gì. Cột Notes có sẵn một câu tóm tắt, ví dụ:

Created on Apple · 12/39 locales · missing screenshot

Đọc câu đó từ trái sang: đã tạo (hay cập nhật) trên Apple · làm được bao nhiêu locale trên tổng số · rồi thiếu những gì. Bấm nút Detail để mở bảng đầy đủ 6 công đoạn của dòng đó:

Thấy gìNghĩa là gìLàm gì
ok Công đoạn đó xong. —
failed Đã thử và hỏng. Bên cạnh có lý do. Xem lý do rồi sửa — file ảnh sai, giá không khớp tier, locale không hợp lệ…
not sent — rate limit Công đoạn này chưa từng chạy. Batch hết lượt gọi Apple trước khi tới nó. Chạy lại import sau khoảng 1 tiếng — phần chưa gửi sẽ được làm nốt.
n/a Dòng này không cần công đoạn đó (vd: không đính kèm ảnh nên không có gì để up). Không phải lỗi. Bỏ qua.

Riêng dòng Localizations có kèm mẫu số, ví dụ 12/39 done · 27 not sent hoặc 37/39 done · 2 failed: de-DE, fr-FR — nên biết ngay còn thiếu bao nhiêu và thiếu locale nào.

⚠️ Lưu ý — "screenshot locked by Apple review" phải sửa tay trên App Store Connect

Nếu câu tóm tắt ghi screenshot locked by Apple review, nghĩa là IAP đó đang ở trạng thái chờ duyệt / đã duyệt và Apple từ chối cho đổi ảnh. File ảnh của bạn không sai, tool cũng không sai — chạy lại import bao nhiêu lần cũng không đổi được. Cách duy nhất là vào App Store Connect đổi ảnh thủ công cho IAP đó, hoặc chờ IAP ra khỏi trạng thái review rồi import lại.

Khi batch tự dừng

Apple giới hạn số lần một tài khoản được gọi API trong mỗi giờ (cửa sổ trượt — không phải reset đúng đầu giờ). Batch lớn có thể chạm trần giữa chừng. Khi điều đó xảy ra, tool chủ động dừng gửi thay vì tiếp tục đâm vào một API đang từ chối, và hiện băng vàng:

"Apple's rate limit stopped this batch early."

Cần hiểu đúng 3 điều:

  • Những dòng đã success vẫn còn nguyên trên Apple. Dừng không hoàn tác gì cả.
  • Những dòng not sent chưa hề được gửi — không có IAP nào được tạo cho chúng, nên chạy lại không tạo trùng.
  • Dòng đang làm dở lúc dừng sẽ thành partial, và bảng Detail của nó ghi rõ công đoạn nào not sent — rate limit.

Việc cần làm: chờ khoảng 1 tiếng cho hạn mức hồi lại, rồi import lại chính file đó. Ở Step 3 những IAP đã tạo xong sẽ hiện thành dòng conflict — chọn Skip cho chúng nếu không muốn đụng lại, hoặc Overwrite để tool làm nốt phần còn thiếu.

Muốn tránh ngay từ đầu: chia file nhỏ hơn (xem Tips bên dưới).

Tips và pitfalls

💡 Tip — Chia batch lớn

Nếu file có hơn 50 IAP, nên chia thành nhiều file nhỏ (mỗi file 30–40 row).     Bước 2 — chọn nước. Cùng dialog chọn territory bạn đã gặp ở Bulk Availabilities. Mỗi nước chọn ở đây thành 1 cột giá + tiền tệ trong file.

    Dòng "as of" ngay dưới hàng filter. Bộ lọc Availability đọc dữ liệu tool đã lưu từ lần đọc Apple gần nhất, nên tool luôn nói rõ dữ liệu đó cũ tới đâu: "Availability as of 2 hours ago · 12 never synced (Unknown)".

    • Mốc thời gian là của item CŨ NHẤT đang hiển thị, không phải mới nhất. Cố ý như vậy: nếu 1 item vừa đọc xong và 40 item còn lại là dữ liệu tuần trước, câu trả lời trung thực cho "tôi đang nhìn dữ liệu cũ cỡ nào" là tuần trước.
    • Khi màn hình trộn dữ liệu nhiều thời điểm cách nhau quá 1 ngày, tool nói thêm "oldest of N; newest …" thay vì giấu sau một mốc duy nhất.
    • Chưa từng sync item nào thì tool ghi "Availability never synced · N unknown" — không bịa ra một mốc thời gian.
    ⚠️ Hai cột, hai câu hỏi khác nhau — đừng gộp

    Apple status trả lời "IAP này đang ở đâu trong quy trình duyệt của Apple?" (APPROVED, DEVELOPER_REMOVED_FROM_SALE…). Availability trả lời "IAP này đang bán ở nước nào?" Hai câu hỏi khác nhau, và trên thực tế chúng thường trùng khớp — nên rất dễ tưởng là một.

    Tool giữ cả hai, hiển thị song song trên từng dòng, và cố ý không dịch giá trị thô của Apple. Lý do: ngày hai cột lệch nhau, bạn phải nhìn thấy điều đó — chứ không phải để tool tự chọn một bên rồi bạn không bao giờ biết.

    ⚠️ Unknown KHÔNG phải "chắc là Available"

    Unknown nghĩa là chưa ai từng hỏi Apple về item này — không phải "đang bán", cũng không phải "đã gỡ". Vì thế item Unknown không lọt vào cả bộ lọc Available lẫn Removed, và ngay dưới dòng "as of" tool nhắc: "Unknown items are excluded from Available and Removed. Use Refresh from Apple to sync them."

    Muốn chúng có câu trả lời: quay lại bảng IAPs, bấm Refresh from Apple (xem mục dưới), rồi mở lại wizard.

    ⚠️ Item bị gỡ SAU lần sync gần nhất vẫn lọt vào file

    Bộ lọc chạy trên dữ liệu đã lưu ("as of"), nhưng lúc export thì tool đọc trực tiếp từ Apple. Nếu một item bị Remove from Sales sau lần sync gần nhất, nó vẫn được tính là Available lúc bạn lọc và vẫn nằm trong file.

    Đây là cái giá của việc lọc 0 request — và là lý do dòng "as of" luôn hiện ở đó. Cần chắc chắn tuyệt đối: bấm Refresh from Apple ngay trước khi export.

    Bấm export xong tool mới bắt đầu gọi Apple. Trình duyệt tự tải file Apple-IAP-export-<appId>-YYYYMMDD.xlsx. Sheet chính tên Apple IAP Export: mỗi item 1 dòng gồm Product ID, SKU Name, Status, Base Country, các cột giá theo nước đã chọn, và các nhóm localization (Locale · Display Name · Description).

    File trông thế nào — 4 điểm đáng biết trước khi mở:

    • Danh sách nước = đúng 175 nước Apple có bán. Trước đây picker hiện 183 nước — một danh sách dùng chung, hồi đó Google cũng lấy (nay không còn: Google dùng đúng 173 nước Play Console bán) — trong đó có 19 nước Apple không bán (Andorra, Monaco, Bangladesh…) — tick vào chỉ tổ ra 19 cột trống vô nghĩa. Nay chúng không còn trong danh sách. Đổi lại, 11 nước Apple CÓ bán mà trước đây thiếu nay đã tick được — trong đó có Nga (RU).
    • Mỗi nước bạn tick = 1 cặp cột (Price · Currency). Tick cả 175 thì file có 175 cặp cột. Nước được hỏi thì được trả lời; không nước nào bị bỏ im lặng.
    • Currency trong danh sách là currency APPLE tính tiền, không phải đồng bản địa. Apple tính phần lớn thị trường bằng USD hoặc EUR: Bulgaria là EUR (không phải BGN), Macau USD (không phải MOP). ⚠️ Vì thế cùng một nước có thể hiện currency KHÁC nhau giữa picker của Apple IAP và của Google IAP — Bulgaria: EUR bên Apple, BGN bên Google. Đó là đúng, không phải bug: mỗi bên hiện đồng tiền mà store của mình thật sự tính. Nga vẫn là RUB — Apple không quy hết về USD.
    • Header ghi tên nước đầy đủ: Price in Thailand (TH), không phải Price in TH. Dòng header thứ 2 vẫn là Price · Currency.
    • Cột giá tự set tay đứng trước, giá Apple tự quy đổi đứng sau, và ô nền vàng nhạt = giá do Apple tự quy đổi (auto-equalized), ô nền trắng = người set. Màu bám theo từng ô, không theo cột: cùng một nước có thể là tay ở item này và auto ở item kia. Nước base của bảng giá đứng đầu nhóm set-tay.
    • 4 cột trái + 2 dòng header bị "đóng băng" (freeze panes) — cuộn ngang qua 175 cột vẫn thấy Product ID và tên nước.

    ⚠️ Ô giá trống và ô giá — KHÔNG giống nhau. Xem mục "Đọc kết quả export" ngay dưới.

Refresh from Apple — giờ đọc cả Availability

Nút Refresh from Apple trước đây chỉ đọc lại State. Từ bản này nó đọc cả cột Availability cho toàn bộ item của app — đây chính là thứ làm cho dòng "as of" ở wizard Export có thể mới lại được.

Bấm xong bạn sẽ thấy toast dạng: "12 state changed · availability: 1022 read". Nếu có item đọc không xong, toast ghi rõ N read, M failed, K not read — ba con số tách bạch, không gộp.

Chi phí: khoảng 1 lần gọi Apple cho mỗi item

Apple giới hạn số lần một tài khoản được gọi API trong mỗi giờ (cửa sổ trượt — không phải reset đúng đầu giờ), giống hệt khung đã mô tả ở Khi batch tự dừng. Refresh một app 1.022 item tốn khoảng 1.022 lần gọi.

  • App nhỏ (vài chục item): thoải mái. Bấm bao nhiêu cũng được.
  • App lớn: đừng Refresh liên tiếp nhiều app lớn trong cùng một giờ. Hai app nghìn item liền nhau là đã ăn hết phần lớn hạn mức của giờ đó, và những việc khác (Bulk Import, Submit, Export) dùng chung đúng cái hạn mức ấy.
  • Chỉ cần Refresh khi bạn muốn số liệu mới — không phải mỗi lần mở trang. Dữ liệu đã đọc được giữ lại, nên mở lại danh sách không tốn thêm lần gọi nào.

Dừng giữa chừng là ĐÚNG, không phải lỗi

Nếu chạm trần giữa chừng, tool chủ động dừng đọc thay vì tiếp tục đâm vào một API đang từ chối, và toast ghi:

"… — availability stopped on Apple's rate limit. Items not read keep their previous "as of" time."

Cần hiểu đúng 3 điều:

  • Những item đã đọc xong vẫn mới. Dừng không hoàn tác gì cả.
  • Những item chưa đọc tới giữ nguyên mốc "as of" CŨ — kể cả Unknown. Tool không đóng dấu thời gian mới cho item mà nó chưa hề hỏi Apple; làm thế thì dòng "as of" sẽ nói dối đúng vào chỗ nó sinh ra để nói thật.
  • Vì thế sau một lần dừng, màn hình có thể trộn nhiều mốc thời gian — và dòng "as of" sẽ nói ra điều đó ("oldest of N; newest …").

Việc cần làm: chờ khoảng 1 tiếng cho hạn mức hồi lại rồi bấm Refresh lại. Item đã đọc xong không phải đọc lại lần nữa.

⚠️ IAP mới tạo chưa hiển thị?

App Store Connect có propagation delay 1-2 phút sau khi POST tạo IAP. Reload trang nếu không thấy IAP vừa tạo. Trang hiện chưa auto-refresh sau create (deferred scope wider — Hotfix 29 chỉ áp dụng Apps list Google).

ℹ️ Export app nhiều IAPs sẽ chậm — bình thường

Export đọc dữ liệu live từ Apple cho từng IAP một (không có cache giá per-territory như Google), nên app có vài trăm IAP trở lên có thể mất vài phút để tạo xong file. Chỉ báo "Generating…" hiển thị suốt quá trình đó là bình thường với app lớn — không phải bug, không cần bấm lại.

⚠️ Dòng có giá để trống trong file export?

Nếu 1 IAP trong file export có tên/status/localization đầy đủ nhưng cột giá để trống, nghĩa là lần fetch giá của riêng item đó bị lỗi tạm thời (network/Apple rate-limit) — item vẫn được liệt kê, không bị bỏ sót. Chạy Export list lại để lấy đầy đủ giá cho item đó.

⚠️ Trống khác —: ô — nghĩa là IAP đó chưa có giá ở nước đó (thường là IAP chưa set giá bao giờ), và export lại cũng ra vậy — muốn hết — thì phải set giá trên App Store Connect. Chỉ ô trống mới đáng chạy lại — và item đó luôn có một dòng ở sheet Export Failures.

Trong section Pricing của form Edit, dưới Base Territory / Price Tier, có khối Custom territory prices. Nó cho phép ghi đè giá của bất kỳ quốc gia nào — kể cả quốc gia đã được pricing template phủ. Những quốc gia bạn không chạm vào giữ nguyên hoàn toàn (giá template, hoặc giá Apple tự quy đổi).

Áp dụng cho cả 3 nguồn giá — Apple base data, Default Template, App-specific Template. Với Apple base data thì custom là nguồn override duy nhất trong lần push.

⚠️ Quan trọng nhất — giá set tay trên App Store Connect sẽ BỊ XOÁ ở lần push kế tiếp

API price schedule của Apple là replace-all: mỗi lần push thay thế toàn bộ bảng giá. Giá bạn set tay trực tiếp trên App Store Connect không nằm trong dữ liệu tool gửi lên, nên lần push sau quốc gia đó âm thầm quay về giá Apple tự quy đổi.

Điều này luôn đúng từ trước tới nay — điểm mới là dialog bây giờ nói ra, và đưa luôn cách xử lý ở cùng một chỗ: Import as custom price. Hãy làm việc này trước mọi lần Update on Apple, với IAP nào từng được sửa giá trên App Store Connect.

Vì sao lại quan trọng

Trước Cycle 44, tool báo thành công dựa trên diff nó tự tính, không phải thứ Google thực sự làm — nên một lần ghi không-thay-đổi-gì trông y hệt một lần ghi thật ở mọi tầng (toast, log, audit). Bug base price vì thế sống ~3 tháng. Giờ tool chỉ báo thành công khi kiểm chứng được.

Gặp "no changes" mà bạn chắc chắn có sửa → item trên Google không giống thứ modal vừa hiện. Kiểm tra lại trên Play Console; log server có dòng [google-iap:update-iap] NO-OP WRITE … (hoặc PARTIAL WRITE kèm danh sách nước nếu chỉ áp dụng được một phần).

Item bị xóa trên Google (Deleted-on-Google)

Nếu item đã bị xóa hoặc đổi tên trên Play Console, trang Edit sẽ hiển thị trạng thái "This item was deleted on Google Play" thay vì form edit thông thường. Không thể edit hoặc Sync item ở trạng thái này. Để khôi phục: tạo lại item trên Play Console rồi Refresh IAPs list — tool tự uncheck flag khi item reappear.

Tips và pitfalls

ℹ️ Hotfix 9 — regionsVersion

Khi Google đổi currency cho 1 country (vd: BG → EUR Jan 2026), convertRegionPrices trả về regionsVersion mới. Tool phải forward giá trị này khi patch — nếu không Google reject 400.

ℹ️ Hotfix 12 — refetch state

Google trả về pre-update snapshot trong PATCH response (state=DRAFT). Tool refetch qua GET để hiển thị state thật — tránh UI hiển thị nhầm Inactive sau khi activate thành công.

Tips và pitfalls

🚫 Customer entitlements không revoke

Bulk Deactivate chỉ stop new purchases. Users đã mua trước đó vẫn giữ entitlement. Nếu cần revoke, dùng Google Play Console refund flow riêng.

Cẩn thận khi deactivate subscription products đang có active subscribers — họ vẫn được auto-renew theo billing cycle hiện tại. Để fully stop, cần cancel từng subscription qua Play Console.

Nếu deactivate nhầm, dùng ngay Bulk Activate để revert. State change idempotent — không phải undo destructive.

Setup Google service account

  1. Tạo service account trên Google Cloud Console

    Google Cloud Console → IAM & Admin → Service Accounts → Create. Service account email pattern: {name}@{project}.iam.gserviceaccount.com.

    Roles cần: Pub/Sub Subscriber, Service Account Token Creator.

  2. Download JSON key file

    Service account → Keys → Add Key → Create new key → JSON. File download về máy. Lưu cẩn thận — file này chứa private key.

  3. Invite service account vào Play Console

    Google Play Console → Users and permissions → Invite new user → paste service account email → assign role App owner hoặc Developer per app.

  4. Upload JSON key vào tool

    Tool: Settings → Google Accounts → + Add Account → drag & drop JSON file. Tool parse + validate:

    • JSON format đúng
    • Có field private_key, client_email
    • Test call Play API → confirm credentials hợp lệ

    Service account được lưu encrypted vào DB.

  5. Set account active

    Trong list accounts, click Set Active bên cạnh account muốn dùng. Apps list tự refresh theo account active (Hotfix 29).

Tips và pitfalls

🚫 JSON key bảo mật

Service account JSON file chứa private key — KHÔNG commit vào git, KHÔNG share qua chat. Tool encrypt khi lưu vào DB. Nếu compromised, vào Google Cloud Console revoke ngay rồi tạo key mới.

Sau khi invite service account vào Play Console, propagation thường mất 5-15 phút. Nếu upload JSON ngay → tool có thể fail validate. Đợi 10 phút rồi retry.

Team có thể thêm nhiều service accounts (vd: VNG + partner studio). Active account quyết định Apps list. Switch nhanh qua nút Set Active — Hotfix 29 đảm bảo Apps list refresh đồng bộ.
