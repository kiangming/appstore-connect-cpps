Export list — item selection, filters, stop-and-preserve

Design mockup for docs/iap-management/design-export-list-item-selection.md. Apple IAP Management only. The country dialog (step 2) is the existing shared component and is not redesigned here.

Cost model (gate G1). Every exported item costs 3 Apple requests (detail + price-schedule stage 1 + stage 2). Today the export sweeps the whole app unconditionally: N=1000 → ~3,005 requests. Steps 1 and 2 below cost zero; only the final Export reads Apple.

Step 1 — optional availability filter (opt-in, priced on the control)
Gate G2: no cheap source exists. The cost is shown, never absorbed.

Filter by availability

⚠ Not free. Reads current availability from Apple for the 12 items you selected — about 12 extra requests. Everything else on this screen is already in hand.

⚠ Why this is not in the main filter bar: classifying availability needs a per-item territory count. Apple’s list include=inAppPurchaseAvailability is free but only proves the resource exists — and “Remove from Sales” is a present resource with an empty territory list (KB §4.12), so presence would label every removed item “Available”.

Step 3 — stopped on rate limit
Three states, kept separate. A stopped run is not a failed run.

Export stopped

⚠ Apple’s rate limit stopped the export after 380 of 400 items. The file has downloaded.
  • ▸ 374 items exported
  • ▸ 6 items partially exported — prices missing (rate limited)
  • ▸ 2 items failed — Apple was asked and refused (reasons in the file)
  • ▸ 18 items not attempted — nothing was sent. Safe to export again.
Sheet “Not exported” in the downloaded file lists all 26, each with its real reason.

⚠ Only NOT_ATTEMPTED is pre-ticked by that button — nothing was sent for those items, so re-sending is harmless. FAILED items are not pre-ticked: Apple was asked and refused, and a human reads the reason first.
